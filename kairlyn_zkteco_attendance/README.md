# kairlyn_zkteco_attendance — ZKTeco 考勤同步

适用于 Odoo 19（企业版或社区版），依赖 `hr_attendance`。

## 部署

1. 把整个 `kairlyn_zkteco_attendance` 目录放进 Odoo 的 addons 路径（Docker 部署时挂载到容器里，并确认 `addons_path` 包含该目录）。
2. 重启 Odoo 容器。
3. 以管理员身份打开开发者模式 → 应用 → 更新应用列表 → 搜索“ZKTeco 考勤同步” → 安装。

不需要 pip 安装任何依赖：通讯库 pyzk 已内置在 `lib/zk`。

**定时任务超时**：同步时会读取设备上的全部记录。实测 xFace600（WiFi）读取 2.6 万条约需 50 秒，记录越多越慢。
Odoo 多 worker 模式下，定时任务默认受 `limit_time_real`（默认 120 秒）限制，建议在 odoo.conf 中设置
`limit_time_real_cron = 600`，避免记录增多后同步被强制中断。

## 升级

正式库和测试库共用同一个 Odoo 容器和 addons 目录时，请按下面的顺序升级（任何版本都适用）：

1. 把服务器上的旧目录移到 addons 目录之外保存（用于回退），再拷入新目录。
2. **先用命令行升级数据库，再重启容器。** Odoo 重启只加载新代码，不会补数据库字段；
   新版本给公司、员工、出勤记录等核心表加了字段时，不先升级就重启，所有数据库都会报错。

   ```bash
   # 查看 Odoo 的启动命令，得到可执行文件和配置文件路径
   docker exec <odoo容器> sh -c 'cat /proc/1/cmdline | tr "\0" " "; echo'

   # 先升级测试库，确认输出末尾没有 ERROR 或 Traceback
   docker exec <odoo容器> <可执行文件> -c <配置文件> -d <测试库> \
       -u kairlyn_zkteco_attendance --stop-after-init --no-http

   # 测试库没问题后升级正式库
   docker exec <odoo容器> <可执行文件> -c <配置文件> -d <正式库> \
       -u kairlyn_zkteco_attendance --stop-after-init --no-http
   ```

   如果 Odoo 进程不是以 root 身份运行，在 `docker exec` 后加 `-u <该用户>`，以免生成的文件权限不对。

3. 正式库升级完成后**立即重启容器**。

测试库升级出错时：把旧目录拷回去即可，正式库和正在运行的 Odoo 都没有受到影响。

版本说明：

- **19.0.1.4.3**：修复设备用户重新出现在考勤机上时同步失败（TypeError … 'DeviceUser'）。
- **19.0.1.4.2**：通讯密码改为文本，用 * 显示、点眼睛图标查看；端口不再显示千位分隔符。
- **19.0.1.4.1**：每日考勤加“补录”按钮。
- **19.0.1.4.0**：给公司、出勤记录加了字段，必须按上面的顺序先升级再重启。
- **19.0.1.3.1**：把员工档案上尚未处理的“待重新计算”标记转入待重算队列，并删除员工表上的这一旧列。

## 首次使用

1. 考勤 → ZKTeco → 考勤机 → 新建：填写 IP、端口（默认 4370）、通讯密码、设备时区。
   “设备时区”填设备时钟当前所设的时区（不一定是公司所在地）。测试连接后“时间差（秒）”接近 0 即为正确。
2. 点击“测试连接”，确认读到序列号和记录数。
3. 点击“立即同步”。同步在后台进行，在“同步日志”中查看进度。
4. 考勤 → ZKTeco → 设备用户映射：先在“员工”中建好档案，再点列表顶部的“按姓名匹配员工”。
   设备姓名与员工姓名完全一致且只有一个同名员工的会自动关联；其余在列表里直接选择员工。
   不需要关联的账号勾选“忽略”。
5. 需要定时同步时，在设备上勾选“自动同步”并设置周期（建议 30 分钟）。
   “失败提醒”：超过设定的小时数没有同步成功，会在考勤机的消息里发提醒，关注这台考勤机的人会收到通知。

## 上线

考勤 → ZKTeco → 清理测试数据 / 上线：

1. 选择考勤机，时间范围留空（全部），**不要**勾选“删除无打卡记录的设备用户”（保留员工映射）。
2. 勾选“同时设为上线”，填上线日期（建议工资周期的第一天）。
3. 输入“删除”确认。

效果：删除 Odoo 里的测试打卡（设备上的数据不动）；考勤机只导入上线日期之后的记录；
“考勤计算起始日期”和“出勤记录生成起始日期”都设为上线日期，之前的每日考勤和自动生成的出勤记录会被删除；
早于上线日期的锁定日期会被清除。向导会提示上线前还有多少条手工建的出勤记录（不会自动删除，可点“查看”处理）。

## 校准考勤机时间

- 以 Odoo 服务器时间为准，按“设备时区”换算后写入考勤机。服务器时间来自宿主机，请在宿主机上配置 NTP 时间同步
  （Odoo 本身没有时间服务器设置）。
- 手动：考勤机表单点击“校准设备时间”（考勤管理员），先显示设备时间、服务器时间和相差的秒数，
  点“立即校准”后马上校准，相差多少都会校准。
- 自动：勾选“同步时自动校准时间”，每次同步下载完记录后，相差超过“自动校准阈值”（默认 30 秒）才校准；
  相差超过“自动校准上限”（默认 1 小时）不自动校准，只在同步日志中报警（通常是时区或服务器时间设置错误）。
- 每次校准都记录在同步日志（方式为“校准时间”或同步日志的“已校准时间”）和考勤机的消息记录中。
- 中和过的测试数据库禁止修改考勤机时间；复制并中和数据库时，会自动关闭考勤机的自动同步和自动校准。
- 时区：设备、员工、Odoo 用户各有自己的时区。设备时区决定设备时间怎么换算；员工时区决定计划上下班时间和迟到早退；
  用户时区只影响显示。在不同国家使用时分别设置即可。

## 每日考勤结果

把原始打卡按员工的工作时间表整理成每人每天一条结果（考勤 → ZKTeco → 每日考勤）。

**准备**

1. 员工 → 配置 → 工作时间表：例如“白班”，周一到周五，上午 8:00–12:00、休息 12:00–13:00、下午 13:00–17:00。
   上午、下午要标好“上午”“下午”时段（半天假按它扣）。每周工时与加班基准都以员工版本上的工作时间表为准。
2. 员工档案：选好工作时间表和时区。不需要考勤的人取消“参与考勤”。
3. 考勤 → 配置 → 设置 → “ZKTeco 考勤规则”：起始日期、迟到/早退容忍、旷工规则、补录规则、重复打卡间隔、换日时间等。

**计算规则**

- 工作日的范围：从当天的“换日时间”到次日的“换日时间”。
- 与上一次有效打卡间隔小于“重复打卡间隔”的打卡视为重复，只保留第一次。
- 工作日：以计划时段的中点为分界（8:00–17:00 即 12:30）：分界前的第一次有效打卡为签到，
  分界后的最后一次有效打卡为签退。打卡都在分界前记为“缺签退”，都在分界后记为“缺签到”，这两种都不生成出勤记录。
- 休息日、公共假日、全天请假：取当天第一次和最后一次打卡（不再要求跨中午），记“休息日出勤”，不扣午休；
  只打一次卡记缺卡。弹性工时也取第一次和最后一次打卡。
- 计划上下班时间取自员工版本上的工作时间表，已扣除公共假日和已批准的休假（与 Odoo 出勤模块一致）。
  请半天假时计划只剩另外半天，例如上午请假，下午 13:05 打卡就是签到。
- 迟到：签到晚于计划上班超过容忍分钟数才计，分钟数从计划上班时间起算；早退同理。
- 出勤工时：签到到签退的时长，扣除本人请假时段；固定工时按工作时间表扣除休息时段。
- 旷工：迟到或早退超过设定的分钟数记旷工半天或一天（分别判断，同一天按重的算）；
  工作日没有打卡、没有请假也没有补录记旷工一天（只有半天班时记半天）。缺卡不算旷工，等补录。
- 弹性工时：不计迟到、早退，不判缺勤。不参与考勤的员工：照常显示打卡，不标记异常，不判缺勤。
- 只有关联了考勤机用户、参与考勤的员工，才会在工作日没有打卡时记为缺勤；当天未结束显示“进行中”。
- 有手工补录的日子：按补录的签到签退计算，照常判迟到、早退、旷工，出勤记录状态显示“已手工补录”。

**请假当天有打卡**

全天请假当天有打卡，或打卡落在请假时段内（超过容忍时间），出勤记录状态显示“请假日有打卡，待审核”，
审核前不生成出勤记录。员工的出勤审批人或考勤管理员处理：

- 员工实际来上班、不休假了：到休假中取消或修改请假，这一天会自动重新计算；
- 请假照休、另外回来工作：在每日考勤点“确认生成”，按实际打卡生成出勤记录，Odoo 按加班规则计算；
- 误打卡或只是回来拿东西：点“忽略”。

**何时重新计算**

- 自动：每小时重算最近 7 天；同步到新打卡、修改员工映射、修改“参与考勤”、修改考勤规则、
  请假批准或取消、公共假日变化、手工补录出勤记录时，都会立即在后台重算。
- 手动：修改工作时间表后，用 考勤 → ZKTeco → 重新计算考勤。
- “考勤锁定日期”及之前的结果不再改动。

## 生成 Odoo 出勤记录

每日考勤核对无误后，把签到签退齐全的日子写入 Odoo 出勤记录（hr.attendance）。
写入后，出勤模块的仪表盘、管理（加班审批）、报表、休假台账，以及按出勤计薪的工资，都会使用这些记录。

**启用**：考勤 → 配置 → 设置 → “ZKTeco 考勤规则” → “出勤记录生成起始日期”（上线向导会一起设好）。

- 点击“一键启用（从今天起生成）”，或直接填写日期（不能早于考勤计算起始日期）。
- 停用后不再生成和更新，已生成的出勤记录保留。

**生成规则**

- 只生成参与考勤的员工、签到签退齐全的日子：正常、迟到、早退、迟到且早退、休息日出勤。
  签到、签退使用真实打卡时间，“方式”为“ZKTeco 考勤机”。
- 本人请假的时段不算出勤：中间请了几个小时假的，拆成请假前、请假后两条出勤记录，避免请假时段被算成加班。
- 缺签到、缺签退的日子不生成（等补录）；缺勤、当天未结束的日子不生成；请假日有打卡的日子审核后再生成。
- 打卡有变化时（例如较晚同步到签退），已生成的出勤记录会自动更新，Odoo 随之重算工时和加班。
- 当天已有手工补录的出勤记录：以手工记录为准，不再生成。
- 人工修改了自动生成的出勤记录：改为手工记录，以后不再自动覆盖。
- 人工删除了自动生成的出勤记录：这一天不再自动生成，可在每日考勤里点击“重新生成出勤记录”恢复。
- 考勤锁定日期及之前的出勤记录不再改动。
- 每日考勤的“出勤记录状态”一列显示每一天的处理结果；筛选“出勤记录需处理”可以找出缺卡、请假日有打卡、
  人工删除、生成失败的日子。

## 补录（补卡）

员工忘记打卡、外勤直接从家出发等，由员工的出勤审批人（部门主管）或人事补录：

1. 最方便：考勤 → ZKTeco → 每日考勤，在缺签到、缺签退、缺勤的那一天点“补录”（表单里是“补录出勤”）。
   会打开 Odoo 的出勤表单：员工和考勤机已经打到的时间自动填好，缺的一侧先填计划时间，改成实际时间即可。
   保存后这一天立即重新计算，关闭窗口就能看到“已手工补录”。
2. 也可以在 出勤 → 概述 → 仪表板 → 新建；当天已有自动生成的出勤记录、只是时间不对的，打开那条直接修改。
   签到、签退都要填，考勤机已经打到的那一侧照着每日考勤里显示的时间填。
3. 选择“补卡原因”（忘记打卡 / 外勤 / 设备故障 / 其他），可以填“补卡说明”。
   签到、签退时间的每次修改都会记录在出勤记录的消息里。

补录规则（考勤 → 配置 → 设置 → ZKTeco 考勤规则）：

- 每人每月因“忘记打卡”最多补录几天（默认 3 天），只能补录最近几天（默认 7 天）；0 表示不限。
- 可以管理所有出勤记录的人事（Officer: Manage all attendances 及以上）不受次数和期限限制。
- 考勤锁定日期及之前的出勤记录（包括自动生成的和手工补录的），只有考勤管理员能新建、修改、删除；加班审批不受影响。

上午没来、下午才来的：请在休假里登记上午的半天假，这一天会自动按下午的班配对；上午其实来了只是忘记打卡的，补录。

## Odoo 端需要的配置（不用开发）

1. **加班规则集**：考勤 → 配置 → 加班规则集。例如：
   - 工作日：按数量，按天，“工时取自员工工作时间表”，支付加班 150%，对雇主有利的容差按公司制度（例如 1 小时）；
   - 周末：按计时，“On any non-working day”，支付加班 200%；
   - 公共假日：按计时，“When employee is off”，支付加班 300%（这条也覆盖员工本人请假的时段，先在测试库试）。
   规则集的 “Rate Combination Mode” 选 “Maximum Rate”（几条规则同时覆盖时取最高倍率，不能相加）。
   休息日按数量的规则也会把整段算成加班，所以几条规则的“对雇主有利的容差”要设成一致。
   容差是门槛：不超过不算，超过则整段都算。修改后在规则集上点 “Regenerate overtimes”
   （会把已审批的加班恢复成待审批，请在正式审批前做）。
2. **加班发钱还是换调休**：规则上勾“支付加班”是发钱，勾 “Give back as time off” 是存入调休余额；
   不同的员工可以用不同的规则集。员工用“加班时间”休假类型请调休（类型上要勾“调休申请”），从余额里扣。
3. **加班审批**：考勤 → 配置 → 设置 → “额外工时验证”改为“由经理审批”；
   员工档案 → 设置 → 审批人 → “出勤”选择审批人（必须是有 Odoo 账号的用户），审批在 考勤 → 管理 中进行。
4. **公共假日**：休假 → 配置 → 公共假日，每年录入。国家调休上班的周末，Odoo 的工作时间表不能单独排班，
   当天会被算成周末加班，审批时拒绝那天的加班即可。
5. **缺勤管理**保持关闭：打开后 Odoo 会给没有出勤记录的日子建技术性记录并记成整天负工时。
6. 员工版本上填写合同开始日期：Odoo 的休假台账只统计有合同开始日期的员工。
7. 正式员工的“工作记录来源”选“工作安排”；临时工（按出勤计薪）选“出勤”，并使用带“休息”时段的固定工作时间表。

## 设计约定

- 对设备只读为主：不删除设备记录、不修改设备用户；唯一的写操作是可选的校准设备时间。
- 原始记录按（设备、用户编号、打卡时间）去重，反复同步不会重复入库。
- 原始记录不可修改；只能由管理员通过“清理测试数据 / 上线”删除，并会写入同步日志。
- 设备上被删除的用户，其映射和历史记录保留。
- 同一编号的姓名变化、或在设备上被删除后重新登记（内部序号变化、消失后又出现），会标记为“需核实”。
  设备管理规则：离职人员的编号不再分配给新人；需要重新录入人脸时，在原用户上直接重录。
- 调整设备时钟的时区时：先同步一次 → 调好设备时钟 → 立即修改“设备时区” → 再同步。
- “导入起始时间”之前的设备记录不会导入。
- 设备序列号与首次记录不一致时同步会中止，防止 IP 被分配给另一台设备后串数据。
- 同步分两步：先从设备下载（不写数据库），再入库。入库时如果有人同时修改了这台设备或用户映射
  （数据库并发冲突），会用已下载的数据自动重试一次；已提交的打卡不会重复入库，统计数字保持一致。
- 同步、测试连接、校准时间、清理数据不会同时访问同一台设备，正在同步时其他操作会提示稍后再试。
- 待重新计算的员工记在独立的队列里（不修改员工档案），并与打卡记录一起提交：同步和计算任务不会争抢同一行数据，
  入库的打卡一定会被计算。
- 同步日志默认保留 90 天（可在设置中修改），清理数据和首次导入的日志永久保留。
